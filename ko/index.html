처리량

모든 tok/s 수치는 모델링된 [추정]이며 실리콘에서 실측한 값이 아니다. 분할상각 메커니즘은 RTL에서 실측했고(하드웨어 weight-load 카운터), 거기에 들어가는 accept rate는 실측된 모델 특성이다. 절대 tok/s는 이 둘의 곱이다.

이 수치가 만들어지는 과정

25.50 GB/token — speculation 없음, PE_M=1 (실측된 메커니즘)
÷ A_eff = 1.87 — 실측 accept rate r₁=0.87
= 13.87 GB/token
→ 1.54 TB/s에서 → ~111 tok/s [추정]

결합된 top glm_q4k_spec_system은 메모리 시스템, PE_M=K+1 배치(batch) verify, accept/reject 루프를 한꺼번에 담는다. 이 top의 하드웨어 카운터는 ALL-ACCEPT에서 가중치 로드 1회당 정확히 K+1개 토큰이 커밋됨을 보여주며(K=3 → 4.00), 커밋된 스트림은 평범한 greedy decode와 일치한다.

Rung 사다리 — 메모리 bandwidth가 결정한다

처리량은 bandwidth에 묶여 있고, bandwidth는 칩의 IO/PHY 예산이 정하며, 그 예산은 rung이 정한다.

  • ① 입증용 FPGA ~5–8 tok/s
  • ② 자금이 투입된 커스텀 보드 ~15–40 tok/s
  • ③ 512GB 상주 박스 ≈80 tok/s

Rung-③ 설계점 ≈80 tok/s [실측 입력 기반 추정] — U(K)와 MTP accept rate r은 둘 다 GLM 계열에서 실측된 값이다. GLM-5.2의 더 깊은 MTP가 공개된 accept depth에 도달하면 ~95.

동작 방식

비용을 낮추기 위해 설계상 NVMe/PCIe bandwidth에 묶어 두었다. MoE expert를 SSD에서 DDR 작업 캐시를 거쳐 대부분 유휴 상태인 Q4_K die로 스트리밍한다.

1 TB NVMe ──► flash_xbar ──► DDR 작업 세트/캐시 ──► ddr5_xbar ──► Q4_K 연산 die ──► 토큰
~467 GB 가중치   N-ch + 깊은 큐   LRU+빈도+prefetch   N-ch 뱅크 분할   MLA + DSA + MoE · ggml dequant → fp32 MAC → bf16

메모리 시스템 전체는 byte-agnostic이다. 주소와 슬롯, ID만 옮길 뿐 가중치 바이트 자체는 건드리지 않는다. 검증은 회귀 테스트에서 바이트 단위로 동일함을 확인하며, 컨트롤러에는 bounded model checking이 더해지고 그중 일부는 unbounded k-induction으로 끌어올렸다. 형식증명은 수치 데이터패스에 전혀 닿지 않는다. 그 평면은 bit-exact 시뮬레이션 golden이 담당한다.

미완 항목

열린 격차 — 대부분은 RTL 저장소가 닫을 수 없는 물리/공정 경계에 놓여 있다.

전체 런타임 GGUF 교차 검증

467 GB GLM 파일을 end-to-end로 실행해 llama.cpp 런타임 argmax와 대조하는 작업. GPU / 대용량 메모리 호스트가 필요하며, 저장소 안에는 아직 도구가 없다.

벤더 PHY IP

DDR5 / NVMe (PCIe) / USB-C PHY는 testbench 스텁 상태다. 라이선스된 PHY IP는 실리콘 rung에서 통합·사인오프한다.

보드 bring-up

FPGA fit은 저장소 안에서 실측했다. 실제 개발 보드에서 돌리려면 보드와 핀 XDC, MIG 브리지가 필요하다.

팹 tapeout 및 dual-port BIST collar

ASIC tapeout은 rung-③ 양산 단계의 종착점이다. on-die 테스트: die에는 이미 인라인 clock gate가 들어 있고, 매크로별 BIST collar는 물리 설계 흐름에서 memory compiler가 생성한다.

모든 tok/s, 비용, 에너지, LOI 수치는 [추정]이다. 실측된 모델 측 입력으로 roofline 모델링한 값이며, 하드웨어에서 실측한 값이 아니다.

main의 Q4_K 트랙 현황. Bit-exact는 독립적으로 재구현한 ggml에 대해 bit-exact라는 뜻이며, dequant 계층에서 실제 GGUF 바이트로 검증됐다. llama.cpp 전체 런타임 동등성은 설계상 계약 범위 밖이다. 처리량과 비용 수치는 모델링된 추정이며 하드웨어 실측이 아니다.
